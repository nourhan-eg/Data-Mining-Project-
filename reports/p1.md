## 2. `src/common/preprocessing.py` — shared preprocessing

### The leakage contract (why the functions are shaped this way)

- `remove_duplicates(df)` is **stateless**: dropping identical rows learns nothing
  from the data, so it is safe to call on the full dataset **before** the split.
  It prints how many rows it removed.
- `handle_missing`, `handle_outliers`, `scale_features` are **fitted** functions:
  every statistic they use (median/mode, IQR bounds, mean/std or min/max) is computed
  from the DataFrame they are handed. That is why they must be called **on the
  training data only**, inside members 2/4's `fit_preprocess` — never on the full
  data, never on the test set.

So the rest of the team can also *transform* the test set, each fitted call records
its statistics on the returned frame in `df.attrs["fitted_stats"]`, and each function
accepts an optional `stats=` argument. Passing `stats` makes it a pure transform
(no refitting). The exact prototypes from the split are unchanged; `stats` is optional
and defaults to `None`.

### The functions

- `remove_duplicates(df) -> df` — drops duplicate rows, prints
  `removed N duplicate rows (before -> after)`. Safe before the split.
- `handle_missing(df, strategy="auto") -> df` — numeric columns are filled with the
  **median**, categorical columns with the **mode**; with `stats=...` it reuses the
  fitted values instead. Fitted: call on train only.
- `handle_outliers(df, columns, method="iqr") -> df` — **caps** (does not drop) values
  outside `[Q1 - 1.5*IQR, Q3 + 1.5*IQR]`; with `stats=...` it reuses the fitted caps.
  Fitted: call on train only.
- `scale_features(df, columns, method="standard") -> df` — `standard` (z-score) or
  `minmax` scaling; with `stats=...` it reuses the fitted mean/std or min/max.
  Fitted: call on train only.

### How members 2/3/4/5 call them

```python
from sklearn.model_selection import train_test_split
import config
from src.common.preprocessing import (remove_duplicates, handle_missing,
                                      handle_outliers, scale_features)

# member 2/4 — stateless cleaning, full data, BEFORE the split
df = remove_duplicates(df)

# member 3/5 — split first
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=config.TEST_SIZE, random_state=config.RANDOM_STATE)

# member 2/4 — inside fit_preprocess(X_train, y_train): fit on TRAIN only
train = handle_missing(X_train)
s1 = train.attrs["fitted_stats"]
train = handle_outliers(train, columns=num_cols)
s2 = train.attrs["fitted_stats"]
train = scale_features(train, columns=num_cols, method="standard")
s3 = train.attrs["fitted_stats"]

# later — transform the untouched test set, no refit
X_test = handle_missing(X_test, stats=s1)
X_test = handle_outliers(X_test, columns=num_cols, stats=s2)
X_test = scale_features(X_test, columns=num_cols, stats=s3)
```

Verified on the real data: Student had 127 duplicate rows (10000 -> 9873), Online
Retail 89 (10018 -> 9929), NSL-KDD 0. Retail's 2477 missing `CustomerID` values and a
few missing `Description`s were filled by the fitted call. IQR capping on NSL-KDD's
skewed count columns capped real outliers (e.g. 1803 values in `dst_bytes`) without
deleting a single row.

## 4. Design decisions

1. **`stats=` extension without changing the prototypes.** The split freezes the
   signatures as fit-on-what-you-are-given. To still give the team a safe transform
   path, the fitted call stores its statistics in `df.attrs["fitted_stats"]` and each
   function accepts an optional `stats` dict. Omitting it keeps the exact frozen
   behavior.
2. **Cap, never drop, in `handle_outliers`** — per the split ("cap, not drop"), so no
   rows are lost between the clean file and the model.
3. **Print-on-every-call.** Each function logs what it did (rows removed, values
   filled, values capped, columns scaled) so runs are auditable in everyone's
   notebooks.
4. **`matplotlib.use("Agg")`** makes the plots work headless (CI, servers); notebooks
   still get `plt.show()` when no `save_path` is passed.
5. **Loaders validate nothing beyond parsing** — cleaning belongs to the pipeline
   steps above, keeping each function single-purpose.
